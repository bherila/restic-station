# Contributing

Thanks for your interest in Restic Station. Two things make this repo unusual — read these before opening a PR.

**The Xcode project is generated.** `ResticStation.xcodeproj` is produced by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml` — never edit the project file directly; edit `project.yml` and run `./scripts/bootstrap.sh`.

**`Core/` and `Helper/` are cross-platform; `App/` is macOS-only.** All logic lives in the `Core` Swift package; `Helper/` (the `restic-station-helper` executable, root SwiftPM package) depends only on `Core` + swift-argument-parser. Both must compile and pass their tests on **Linux** as well as macOS — that is the `linux` job in `.github/workflows/ci.yml` (`swift build && swift test` at the repo root, plus `swift test --package-path Core`, in a `swift:6.1` container), and it is a required check: a Linux-only compile error in `Core/` or `Helper/` fails it. Darwin-only API (`DistributedNotificationCenter`, AppKit, ServiceManagement, the Keychain `security` subprocess) belongs in `App/` or behind `#if os(macOS)` / `#if canImport(Darwin)`. Locally: `swift build`, `swift test --package-path Core` (works with a bare Homebrew Swift toolchain, no Xcode.app required — see `docs/testing.md`). Building/testing the Linux **static release** binary (Apple's Static Linux SDK, musl) is a separate, heavier path covered by `scripts/package-linux.sh` and the `release-linux`/`linux-integration`/`linux-runtime-verify` CI jobs — not needed for an ordinary `Core`/`Helper` change. Tests use Swift Testing (`import Testing`, `@Test`, `#expect`) — not XCTest.

**The spec docs in [`docs/`](docs/) are normative.** `architecture.md`, `data-model.md`, `restic-cli.md`, `scheduling.md`, `keychain-and-fda.md`, `ui-spec.md`, `testing.md`, and `linux.md` define the intended behavior; the code implements them. If your change alters behavior, update the relevant doc in the same PR — a PR that makes code and docs disagree will be asked to reconcile them. State which platform(s) a change affects; most docs other than `ui-spec.md` (macOS-app-only) cover both. Key invariants to preserve (each has negative tests — keep them): all mutating restic operations go through `restic-station-helper`; keychain access only via the `/usr/bin/security` subprocess with `-T /usr/bin/security` at item creation (macOS); the Linux `secrets.json` is created `0600`/`0700` and every read re-verifies the mode; never `forget` with an empty retention policy, never `forget`/`prune` a mirror that isn't caught up to the primary; `machine.json` is host-local and is never read or written by anything that touches `config.json`'s shared state.

CI must be green before merge: `linux` (Core + Helper on Linux), `macos` (app build, Core tests, real-restic integration script), `release-linux` (static Linux binary, both architectures), `linux-integration` (that binary's fixture-import flow against real restic on a bare Ubuntu VM), and `linux-runtime-verify` (the binary runs unmodified across several userlands with no Docker Desktop / colima needed locally — see `.github/workflows/ci.yml`).
